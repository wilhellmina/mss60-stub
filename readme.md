# 241E censor_off パッチ解説

> i don't take any responsibilities while using this binary. if you not understand what this does then just dont use it

## 何をしたか(要約)

MSS60(241E)のFullバイナリに対し、**EWS4 SKロックイン時にUC3F censor bitが立って
BDMアクセスが奪われるのを防ぐ**パッチを3箇所(計25バイト)適用した。

- censor設定関数を**逆転**(censorを11に立てる→00にクリアする)
- **ブートフック**を追加し、この関数が毎ブート必ず1回呼ばれるようにした
  → **このbinをフラッシュすれば次回ブートで自動アンロック**(診断操作不要)

|---|---|---|
| `censor_off.bin` | パッチ済みFullイメージ(5,242,880 bytes) | `cc63000889e285bd21888e9c0acebffc` |
| `censor_off.gzf` | 同内容のGhidraプロジェクトエクスポート |  |

## 背景

- `inj_uc3f_censor_set` @ Ghidra `0x0047549C`(ファイルオフセット `0xF549C`)は
  MPC561/563 UC3Fの「Setting Censor」手順(RM 21.3.11.2)を実装する関数。
  EWS4 SKロックイン(診断0x2E DID 0xC001、呼び出しは `inj_diag_2E_C001_EWS4_SK` @ 0x4BEC94)から
  車の生涯で1回だけ呼ばれ、シャドウのCENSOR[0:1]=11(information censorship)を書き込む。
  以降、BDMからメモリが見えなくなる。
- 純正コードには開発者向けの抜け道がある: ブート時のCS0(0xC00000番台)RAMテストで
  エミュレータ/キャリブレーションRAMを検出すると `boot_hw_flags`(0x3F8010) bit 3が立ち、
  censor設定がスキップされる。実車ブートでは立たない。
- IGN側にも同一構造の `ign_uc3f_censor_set` @ `0x006E2A8C` があるが、**静的な呼び出し元は存在しない**
  (デッドコード)。念のため同じパッチを当てているが、効果はない(保険)。

## パッチ詳細

### 1. censor設定関数の逆転(INJ側)

| Ghidraアドレス | ファイルオフセット | 元 | 新 | 意味 |
|---|---|---|---|---|
| `0x004754CC` | `0x0F54CC` | `41 82 01 30` | `40 82 01 30` | `beq`→`bne`: エントリチェックを反転し、**censor==11(ロック済み)のときだけ**本体を実行 |
| `0x00475558` | `0x0F5558` | `65 4A 03 00` | `55 4A 02 0A` | `oris r10,r10,0x300`→`rlwinm r10,r10,0,8,5`: インターロック書き込み値のCENSORビット(bit24-25)を**セット→クリア** |

マスク検証: `rlwinm r10,r10,0,8,5` のマスクはMSB番号8→5(ラップ) = `0xFCFFFFFF` = `~0x03000000`。
CENSOR=00を書く。1→0方向の書き込みなのでフラッシュ的に正当。

### 2. 同上(IGN側・保険)

| Ghidraアドレス | ファイルオフセット | 元 | 新 |
|---|---|---|---|
| `0x006E2ABC` | `0x362ABC` | `41 82 01 30` | `40 82 01 30` |
| `0x006E2B48` | `0x362B48` | `65 4A 03 00` | `55 4A 02 0A` |

### 3. ブートフック(毎ブート自動呼び出し)

| Ghidraアドレス | ファイルオフセット | 元 | 新 | 意味 |
|---|---|---|---|---|
| `0x00010020` | `0x010020` | `00 01 58 3C` | `00 01 EE 98` | アプリヘッダのエントリポインタを本来の`0x1583C`からスタブ`0x1EE98`へ |
| `0x0001EE98`(16バイト) | `0x01EE98` | `FF`×16 | 下記スタブ | 消去済みパディング領域にスタブを配置 |

スタブ(`inj_censor_off_boot_stub`):

```
7C 08 02 A6   mflr r0                 ; ブートへの戻りアドレス(0x6A4)を保存
4C 56 60 01   bl   0x47549C           ; inj_uc3f_censor_set を呼ぶ
7C 08 03 A6   mtlr r0                 ; LR復元
4B FF 69 98   b    0x1583C            ; 本来のアプリエントリへ(そのまま起動)
```

仕組み:
- ブート(`inj_boot_select_app_or_install`)は `lwz r10,0x20(0x10000); mtspr LR,r10; blrl`
  でアプリエントリを呼ぶ。ポインタをスタブに向け、スタブからcensor関数を呼んでから
  本来のエントリへtail-jumpする。LR保存/復元するのでブート側への復帰はそのまま。
- `0x1EE98-0x1FFFF`は消去済みの未使用領域(参照は`FUN_000159b0`内のデッドブロックのみ)。
- ヘッダチェック(`inj_boot_check_app_hdr_10000`)はエントリポインタの**範囲(0x10000-0x1FFFF)のみ**
  検証し、チェックサムはない。0x1EE98は正当な範囲内。

## 動作仕様

```
電源ON → ブート → アプリエントリ呼び出し(0x10020 = 0x1EE98)
  → スタブ: inj_uc3f_censor_set を1回呼ぶ
      censor=00(未ロック) → 即return 0(約10命令、実質ゼロコスト)
      censor=11(ロック済み) → シャドウへCENSOR=00書き込み = アンロック
  → 本来のアプリ起動(通常どおり)
```

- **新品/未ロックECU**: SKロックイン時にcensor設定がスキップされ、censor=00のまま
  (SKロックイン自体は正常完了、戻り値0を返す)。ブートフックでも何もしない。
- **ロック済みECU**: このbinをdiagフラッシュ → 次回ブートで自動アンロック。
- 返り値仕様は不変: 0=成功/未ロック、0xFE=IWS無し、0xFF=HVSタイムアウト。
- 従来のSKロックイン経路(cal RAMゲート付き)もそのまま動く(フックと二重保険)。

## 対stock全差分(25バイト)

```
0x010022-0x010023   0001ee98 へのポインタ下位2バイト
0x01ee98-0x01eea7   ブートスタブ16バイト(うち0xFF 1バイトは不変)
0x0f54cc            41→40 (INJ beq→bne)
0x0f5558,0x0f555a-0x0f555b  INJ oris→rlwinm (3バイト、0x4Aは不変)
0x362abc            41→40 (IGN beq→bne)
0x362b48,0x362b4a-0x362b4b  IGN oris→rlwinm (3バイト、0x4Aは不変)
```

## 元に戻すには

- **フックだけ無効化**: `0x10020`を`00 01 58 3C`に戻す(スタブの残置は無害)
- **censor反転だけ戻す**: 上表の4地点を元バイトに戻す
- 完全に戻す: stock binを流す

## 注意事項

1. **チェックサム**: INJ INT(0x10000-0x1FFFF)とINJ EXT(0x400000+)の2ブロックに触れている。
   フラッシャー/ECUがチェックサム検証する場合は`MSS60_Binary_Modification_Tool`等で修正すること。
2. **ステージド更新不可**: `inj_boot_install_staged_block`は0x10000-0x1FFFFを消去して
   ステージドイメージで書き直すためフックが消える。このbinは**フルフラッシュ専用**。
3. 実車投入前にベンチでのブート/BDM接続確認を推奨。
4. censor=11のECUでアンロックを試みる際、UC3Fのshadow読み出し(IWSチェック)が
   censorship下でも通るかは実機確認済みでない(失敗しても0xFEで无害に終わる)。
